# 2026-11-13 재개 기록

사용자가 `진행 재개해`라고 요청해 11월12일 중단 체크포인트부터 재개했다.
현재 프로그램은 진행 중이며 자동 재개나 예약 실행을 새로 만들지 않았다.
이 문서의 첫 체크포인트는 Native34의 실제 읽기 검증 unit64 완료다.
이전 전체 이력은 [11월12일 인수인계](LOOP_HANDOFF_2026-11-12.md)에 보존한다.

## 이번 재개의 조건과 우선순위

사용자는 Volt 276과 Keystation 88 MK3를 한국 시간 2026년11월13일 오전6시30분까지 연결한다고 알렸다.
사용자가 확인한 연결은 USB뿐이며 출력과 입력을 연결한 물리 루프백 케이블은 없다.
하드웨어가 필요한 유한 검증을 일반 프리셋 작업보다 먼저 배치한다.
실제 왕복 지연·물리 External Effect ping은 배선이 필요한 미검증 항목으로 남긴다.
USB 연결만으로 CV 출력 격리나 실제 키 입력을 성공 처리하지 않는다.

사용자는 REA 최신 버전 갱신과 Craft Anything 활용도 요청했다.
기존 Ghidra와 byte-bound 증거를 재사용하고 구체적인 미확인 receiver를 조사할 때 새 분석을 수행한다.
Hopper는 사용하지 않는다.

단위 종료 보고에는 다음 항목을 포함한다.

- 완료 범위와 최종 원본 일치 여부.
- 검증 실행 시간과 UI·정리를 포함한 시간의 구분.
- 완료·잔여 수와 다음 단위.
- 전체 예상 잔여 시간 범위와 추정이 달라진 근거.
- 별도 하드웨어 조건과 현재 연결 마감 시각.

## 재개 preflight 완료

Git의 중단 체크포인트는 `f27e9ec`이며 제품 소스는 `3815714`다.
완료된 대규모 sweep을 재실행하지 않고 설치 Native34 R2와 main 실행 파일을 대조했다.
네 native 파일과 bridge 세 파일은 검토한 패키지·wire 해시와 일치했다.
세 소유 곡의 저장 해시도 중단 원본과 같았다.
앱과 기존 MCP owner가 종료된 상태에서 새 artifact binding을 구성했다.
이전 session·document·instance와 UI 완료 flag는 재사용하지 않았다.

중단 guard의 사본을 보존한 뒤 기존 유한 launcher에 unit64만 넣었다.
완료된 unit62·63을 다시 실행하지 않았다.
하드웨어 우선순위 때문에 unit65는 이 첫 실행 큐에 넣지 않았다.

## Unit64 저장 Chorder 모델 읽기 완료

실제 Fender Studio Pro8.1.1 Build113103에서 Native34 R2의 `chorder_chords_get`를 호출했다.
현재 문서·bridge session·Chorder instance를 새로 바인딩한 읽기 전용 단위였다.
각 pass는 offset0·16·32·48·64·80·96·112와 limit16으로 전체128개 입력을 읽었다.
이 전체 pass를 두 번 수행해 총16회의 새 serializer 관찰을 얻었다.

원래 진단 fixture에서 한 입력의 출력 음정5개와 다른127개 입력의 빈 목록을 확인했다.
두 pass의 전체 모델은 같았고16개 capture는 모두581바이트의 원본과 일치했다.
페이지마다 fresh capture를 읽으므로 atomic snapshot이라고 표현하지 않는다.
이 결과는 현재 저장 모델의 읽기 검증이며 GUI child 이름과 MIDI 출력 음정의 일반 매핑은 확정하지 않는다.

전체908개의 typed schema·값·normalized·display·access metadata를 전후 두 쌍으로 비교했다.

## USB 하드웨어의 수동적 인식 확인

Root가 실행한 CoreMIDI inventory는 client·port를 생성하거나 MIDI message를 보내지 않았다.
Keystation의 USB MIDI·Transport와 Volt의 MIDI source·destination이 online으로 관찰됐다.
기존 bridge의 virtual wake source는 물리 키보드 입력과 별개다.
실제 건반 event를 받거나 DAW가 그 포트를 입력으로 사용한다는 증거는 아직 없다.

OS Core Audio inventory는 Volt를48kHz·2입력·2출력 장치로 보고했다.
Volt는 OS default output이었지만 OS default input은 다른 장치였다.
이 값은 DAW의 선택 장치를 증명하지 않으므로 실제 Audio Setup과 I/O 목록을 별도로 확인한다.
USB inventory의 빈 배열을 키보드 부재로 해석하지 않고 CoreMIDI의 실제 endpoint 관찰을 사용했다.

이 체크포인트의 설치 서버는43개 도구다.
`hardware_devices`와 유한 `midi_input_observe`는 별도의 Rust 소스 작업 중이며 아직 설치·실기 완료로 기록하지 않는다.
향후 두 도구가 모두 통합되면45개가 되지만, 그 수를 현재 검증 도구 수로 사용하지 않는다.

## REA와 Craft Anything 상태

공식 배포 metadata에서 REA6.9.0과 Craft Anything0.6.1을 확인했다.
기존 Node26.10.0은 REA6.9.0의 요구 범위에 들지 않아 별도의 portable Node26.12.1을 준비한다.
공식 Node archive, REA npm tarball과 Craft macOS CLI ZIP의 실제 다운로드 해시를 배포 값과 대조했다.
이 첫 체크포인트에서 새 runtime 실행·등록 갱신·Ghidra 분석 성공은 아직 확인하지 않았다.
패키지 획득을 현재 세션의 MCP 재연결로 표현하지 않는다.

REA와 Craft의 설치·실행 증거는 이후 해당 단위가 끝났을 때 갱신한다.
Fender MCP 서버는 native Rust로 유지하고 분석 도구를 제품의 runtime 의존성으로 넣지 않는다.
