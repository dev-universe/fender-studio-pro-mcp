# 2026-11-20 CV 조사와 FabFilter 호환성 인수인계

내장 플러그인 대기열은 43개 중 15개 완료, 28개 잔여다. 소프트웨어 24개와 하드웨어 4개를 구분한다. [11월 18일 인수인계](LOOP_HANDOFF_2026-11-18.md#11-빠짐없이-이어갈-28개-완료물)의 완료 조건을 그대로 사용한다. FabFilter는 별도 대기열이며 설치에서 발견한 VST3 23개 버전을 기준으로 삼는다.

## CV 뮤트와 그룹 조사

- 보존된 R84와 R85의 조작 전 읽기에서 채널 67개와 모든 보고 필드가 일치했다. CV Instrument의 오디오 채널은 인덱스 55, 콘솔 표시 번호 56이다. 이 시점에 뮤트 49개, 솔로 0개를 읽었다.
- 당시 보존한 해시와 현재 Scratch 저장본이 일치한다. 저장된 EditGroupManager는 편집 그룹 0개, 그룹 일시 정지 상태 0을 기록한다. 믹서에 있는 채널 종류별 분류와 가시성 동기화는 뮤트 연결 설정과 별개다. 실제 Console의 Mix Group 목록, 선택 집합과 일시적인 연결 상태는 아직 읽지 못했다.
- 설치된 8.1.1의 스킨은 트랙 목록의 전역 M을 `anyMute`와 `Console > Global Mute` 명령에, 콘솔 채널 M을 별도 `mute`에 연결한다. 콘솔 채널 M은 가로 쓸기를 지원한다. 같은 버전의 기본 명령 목록에 전역 뮤트 단축키 Command+Shift+M이 있다. 이 단축키가 입력됐다는 측정은 없다.
- R84 성공 직후 화면에는 콘솔 포커스 표시가 있다. R83 중단 화면은 편곡 창에 포커스 표시가 있고 R85 중단 화면에서는 콘솔 포커스 표시가 보이지 않는다. R85 중단 화면의 포인터와 Control Link는 CV 채널 뮤트를 가리키며 값은 0이다. 전역 M과 화면에 보이는 트랙 3~7의 M이 함께 꺼졌다. 이 관찰로 전체 채널의 변경이나 전역 명령 실행을 확정할 수 없다. R83은 API 호출로 실패했으므로 GUI 포커스만으로 두 실패를 설명할 수 없다.
- 다음 단위는 Native59의 새 Scratch에서 실제 Console Groups와 선택 상태, 콘솔 포커스, Control Link, 전체 채널 기준값을 읽는 것이다. 이후 별도 진단에서 필요하면 중립 영역으로 콘솔에 포커스를 주고 전체 기준값이 같은지 먼저 확인한다. 한 번의 채널 클릭을 시험할 때는 마우스 위치, modifier 사용 여부, 직후 화면과 이상 시에도 허용할 읽기 전용 확인 한 번을 사전에 정한다. 뮤트 setter의 검증과 Native60 lifecycle 검증은 별도다. CV가 이미 뮤트되고 외부 포트가 모두 None인 별도 Scratch를 검증하면 lifecycle 시험 중에 뮤트를 조작할 필요가 없다.

시작 옵션을 확인하려던 앱 선택이 Studio Pro를 시작했다. MIDI 환경설정 변경 및 외장 장치 재연결 안내에서 멈췄다. 재연결을 선택하지 않았고 일반 종료 단축키에 반응하지 않아 이번에 시작한 프로세스만 종료했다. 사용자 곡이나 Scratch를 열기 전이었으며, MCP 요청은 0개다. 종료 후 저장본 10개, CoreAudio와 MusicDevices 설정 2개, DAW 실행 파일 1개가 보존값과 일치했다. 기존에 실행 중이던 스캐너 3개는 그대로다. VST 스캔 설정은 시작 시 스캔을 사용하며 이번 시작 중 스캔 로그와 플러그인 캐시가 갱신됐다. 다음 실제 확인은 타사 코드의 로딩 범위부터 통제한다. PreSonus의 [시작 및 복구 옵션 안내](https://support.presonus.com/hc/en-us/articles/360057405992-Startup-and-Recovery-Options-in-Studio-One-5-2-and-higher)는 Shift 시작을 설명한다. 이번 8.1.1 실행에서 해당 옵션을 확인하지 못했다.

R83·R84·R85는 닫힌 세션이다. 기존 Native60의 실제 lifecycle 호출은 0회다. [PR #6](https://github.com/dev-universe/fender-studio-pro-mcp/pull/6)은 재개 시점에 CI 두 항목이 통과한 초안이었다. CV 출력 경로와 프리셋 보존 조건은 그대로 적용한다.

## FabFilter 공식 VST3 조사

[FabFilter 공식 다운로드](https://www.fabfilter.com/download)와 [이전 버전 다운로드](https://www.fabfilter.com/support/downloads)에서 최신 번들의 14개와 설치 목록에 있는 이전 버전 9개를 받았다. 패키지의 FabFilter 배포자 인증서와 Apple 공증을 확인했다. 패키지 스크립트를 실행하거나 기존 설치를 교체하지 않고 별도 위치에서 추출했다. 아래 23개는 모두 설치본과 버전 표기가 같다. 실행 파일 SHA-256은 23개 모두 다르며, 조사한 설치 VST3는 모두 배포자 인증서 없는 서명이었다. 공식본의 별도 검증 결과를 설치본의 동작으로 환산하지 않는다.

공식 Pro-Q 4.13의 arm64 공개 `GetPluginFactory` 진입점을 REA 6.9.0과 Ghidra 12.1.4로 확인했다. Ghidra 작업은 약 48초에 끝났다. Craft Anything 0.6.1은 별도 프로젝트에서 같은 파일과 진입점의 단일 분기를 찾았다. 공개 API를 호출한 별도 검사에서는 오디오 컴포넌트, 편집 컨트롤러와 호환성 클래스가 일치했다. 정적 분석은 공개 인터페이스 경계에 한정했다.

서명을 검사한 공식 VST3 23개를 하나씩 별도 프로세스에서 열었다. [Steinberg 공개 VST3 API](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/classSteinberg_1_1Vst_1_1IEditController.html)로 컴포넌트와 컨트롤러를 연결하고 각 인덱스의 파라미터 설명과 정규화 현재값을 읽었다. 전체 12,478개이고 번들별 ID는 중복이 없었다. 23개에 읽기 전용 플래그가 있었고 9,125개에 자동화 가능 플래그가 있었다. 모두 연결을 해제하고 종료했다. 이 수는 해당 검사에서 노출된 목록이다. 플러그인 UI 내부 기능, 다른 모드의 동적 파라미터, 오디오, 쓰기 또는 프로젝트 재시작을 검증한 수치와 구분한다.

Studio Pro 8.1.1의 디스크 캐시에는 23개 전부가 등록돼 있다. 이펙트 20개와 악기 3개다. 23개 모두에서 캐시의 클래스 ID가 공식 팩토리의 오디오 컴포넌트 ID와 표기 차이를 제외하고 일치했다. 캐시는 시작 중 기록된 정보다. 실제 MCP 카탈로그와 곡 내 인스턴스는 다음 검증에서 읽는다.

로컬 프리셋 폴더에는 일반 `.ffp` 파일 5,037개와 서로 다른 4바이트 시작 패턴 26개가 있었다. 파일명, 내용, 사용자 경로 및 바이너리 분석 원본은 게시하지 않는다. `.ffp` 개수와 호스트가 현재 플러그인 인스턴스에 발급한 프리셋 개수는 별개다. DAW나 플러그인에 프리셋을 불러오거나 저장하지 않았다.

공식 23개는 격리 검사에서 각각 VST3 프로그램 목록 1개와 슬롯 128개를 보고했다. 성공한 비어 있지 않은 프로그램 이름은 0개였다. [FabFilter의 프리셋 설명](https://prod.fabfilter.com/help/pro-q/presets/loadingpresets)에 따르면 MIDI 프로그램 변경을 켜서 프리셋을 부를 수 있지만, 파일을 추가하면 번호가 바뀔 수 있다. 이 경로의 번호와 실제 프리셋을 검증하지 않았다. 별도 쓰기 적격 검사는 연속형이고 표시되는 파라미터에 적용하되 목록·프로그램·바이패스 항목을 제외했다. 이 조건을 모두 만족한 항목이 없어 setter 호출은 0개다. 자동화 가능 플래그만으로 쓰기·복원을 통과 처리하지 않는다.

## 정확한 플러그인 삽입 후보

`tracks_edit`에서 `addPlugin`과 `addInstrumentTrack`에 선택적으로 `classId`를 지정할 수 있다. 현재 `plugin_catalog`가 반환한 이름과 ID가 같은 행에서 발견됐을 때만 해당 호스트 클래스의 삽입을 요청한다. 이름으로만 호출하는 기존 사용법도 지원한다. 선택된 ID는 실제 곡에 생성된 인스턴스 ID와 구분한다.

첫 구현을 독립 검토했을 때 이전 EditTask가 새 필드를 무시해 동일 표시 이름의 첫 번째 플러그인을 삽입했다. 수정 커밋은 정확한 선택 요청에 별도 내부 동작 이름을 사용한다. 구버전 브리지와 EditTask 원본을 사용한 재현에서 이펙트와 악기 두 요청 모두 거절됐고 대상 동작이 실제로 만든 트랙이나 플러그인은 0개였다. 기존 작업 묶음은 항목별 결과를 유지한다. 구버전 거절의 상위 MCP 결과는 확인 불가로 표시될 수 있다.

최종 코드 `57faf1784d9dfabdd6b0dc4318408728182a3bbe`에서 Rust 1.88 포맷·Clippy·185개 테스트와 release 빌드, JavaScript 389개 테스트가 통과했다. 별도 검토자는 같은 코드에서 수정 후 원본 구버전 재현과 대상 JavaScript 7개 검사를 다시 통과했다. [PR #8](https://github.com/dev-universe/fender-studio-pro-mcp/pull/8)은 실제 8.1.1 삽입 및 제어 검증을 기다리는 초안이다.

## 이어갈 순서

1. CV는 현재 설치 Native59에서 그룹·포커스 읽기부터 한다. 타사 플러그인 스캔 없이 시작할 수 있는 환경을 확인하고 현재 프로세스·설정·저장본과 잠금을 다시 확인한다. 후보를 설치하려면 기존 Native60 정상 분석과 보존된 설치본을 먼저 재바인딩한다.
2. FabFilter 삽입 소스는 별도 브랜치 `feature/plugin-class-selection`에서 검증한다. 기존 `plugin_catalog`의 호스트 이름과 `classId`를 `tracks_edit`의 `addPlugin` 또는 `addInstrumentTrack`에 함께 준다. 요청할 때는 현재 호스트가 반환한 ID를 그대로 사용한다. 설치된 DAW 래퍼가 실제로 보고하는 클래스와 새 인스턴스 ID는 삽입 뒤 다시 읽는다.
3. 서명이 확인된 플러그인을 사용할 수 있는 8.1.1 Scratch에서 Pro-Q 4 이펙트와 Twin 3 악기를 먼저 검증한다. 호스트 카탈로그, 지정 삽입, 고유 이름과 ID를 가진 쓰기 가능한 파라미터의 변경·별도 읽기·원복, 저장하지 않고 닫기를 확인한다. 기존 범용 provider 사용 가능성을 이때 확정한다.
4. 두 기준 사례 뒤 나머지 제품에 같은 계약을 적용한다. 페이지 경계, 매개변수 이름 충돌, 모드별 목록 변경, 불연속 값 및 호스트 분류를 버전별로 기록한다. 파라미터, 변경·복원, 상태 캡슐, 프리셋 리콜, 재시작 지속성의 완료 기준은 각각 확인한다.
5. 프리셋은 호스트의 클래스 일치 항목 발급을 먼저 확인한다. 해당 경로로 제공되지 않는 FabFilter 내부 메뉴·프리셋 형식은 별도 연구로 남긴다. 빈 카탈로그나 단독 파일 존재를 불러오기 성공으로 세지 않는다.

종료 시 확인한 오디오 장치 목록에는 Volt 276이 없었다. 실제 건반 입력과 물리 오디오 왕복은 별도 장치 검증 사항이다. 이번 작업에서 설치본 교체, Native60 설치, 곡 저장, 플러그인 파라미터 쓰기 요청은 없었다.
