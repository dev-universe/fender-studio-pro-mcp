# Splitter drag on a Mixtool output leading to a merger

The independently owned scratch copied a saved Studio Pro 8.1.1 Build
113103 graph. It contained two nested splitters with two Mixtools in
series on one inner branch. Both exact devices independently resolved
the same live folder, graph, and six ordered node records. The second
Mixtool's output led directly to the inner merger, while the first
Mixtool led to the second.

One Routing editor drag moved from the displayed Splitter control to a
visible connector segment just below the second Mixtool, before the
inner merger. The witness covers the visible source and destination.
An active drop indicator was unavailable. This is one gesture trial
on the outlet to a merger, following the earlier trial on the serial
link between two Mixtools. [Fender Routing View manual](https://fenderstudiopromanual.fender.com/en/Content/Mixing_Topics/Channel%20Overview%20and%20Editor.htm)

The editor showed no graph change. Two independent post-drag readings
matched all six original nodes and seven ordered edges, both 72-record
typed providers, the mixer, and the timeline. The drag produced no
verified insertion. The known native slot-to-merger operation has
its own successful evidence. Undo and Save were omitted.

An initial attempt stopped on the diagnostic's comparison of differently
cased UUID strings. Comparing the two IDs in canonical form against the
captured responses passed. The gesture trial then used a fresh process
and independent copy. The first attempt took 32 requests in 3.608
seconds with the app open 94.172 seconds. The gesture trial used 97
requests in 63.680 seconds with the app open 107.578 seconds. All eight
capture tokens across both runs were released. Both scratch files and
the source matched their original digests. Eighteen managed installation
files and nine app profile files were restored and verified after each run.
