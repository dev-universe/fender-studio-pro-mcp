# Chorder software keyboard press and release

R329 tested a single live software-origin note in Studio Pro 8.1.1 build 113103 on macOS arm64 with the `d743ca67` build. The trial used an empty owned Music track with Chorder and Mojito. Playback, recording and loop were off. Mojito was muted and Main was silent. The track took input only from the installed Fender Qwerty Keyboard for the event.

The software keyboard showed octave C3, 80% velocity and sustain off. One bounded 2,000 ms click on its Q key sent MIDI 60 and released it independently of MCP polling. There were 13 complete held observations in one contiguous interval among 173 snapshots. The 30 sampled typed DSP roles showed the one live input and the five live output notes 60, 63, 67, 70 and 74. Scheduled activity, adjacent-pitch controls and the direct GUI-input roles remained neutral. Two further readbacks after the acknowledged release showed all 30 values neutral.

The independent full settings and chord reads matched the earlier baseline. Restoring the track input through the Inspector caused the host to turn monitor off automatically. The primary cleanup stopped when that transition differed from its expected sequence. A fresh serialized owner bound the same document and instance, read neutral twice, confirmed monitor and arm were both off, restored the remaining Mojito mute state and reread the exact original mixer, chord, writable values and neutral state. The focus and routing recovery did not send another note.

The active event run used 242 MCP requests in 119.553 seconds and the final cleanup used 39 in 3.820 seconds. The host exited normally after 497.946 seconds, including the initial preparation that expired before any note was sent. The scratch closed without saving. The original channel input, device configuration, keyboard mapping, 18 managed files, application profile and protected source inputs were verified or restored. Duplicate or ambiguous inputs, receiver context loss and physical MIDI remain separate cases.
