# 작업 재개 안내

먼저 [11월 20일 실제 검증 인수인계](LOOP_HANDOFF_2026-11-20_LIVE.md)와 `RESUME_STATE.json`을 확인한다. CV 콘솔 그룹, 뮤트 왕복, Output01 구조 조회, Output03 컨트롤러 정체를 실제 8.1.1에서 확인했다. R106에서는 MCP로 공장 프리셋의 설정만 직접 적용하고 설정 97개와 미할당 포트 일곱 개를 확인한 뒤 원복했다. 해당 코드가 공개 main에 병합됐고 실제 배정된 포트의 보존 검증이 남았다. Pedalboard는 R102의 별칭·직접 슬롯 토글과 R107의 호스트 바이패스 왕복을 확인했다. 남은 별칭과 랙 편집을 이어간다. Impact R118의 편집기 `St 2` 활성·원복 뒤 믹서와 값 4,262개를 확인했고 R119에서 저장·재개를 검증해 파일의 출력 구조 읽기를 공개했고, 실시간 MCP 제어를 이어간다. R123·R124에서 Rumble의 공장 프리셋이 모델을 바꾸는 것과, 프리셋을 거치지 않아도 상태 불러오기 시 내부값 정밀도 차이가 누적되는 것을 확인했다.

공식 FabFilter VST3 23종에서 실제 삽입과 열거를 마쳤다. R45까지 쓰기 가능 값 12,455개 중 5,300개를 개별 왕복 검증했다. Timeless 2의 이름 있는 값 705개, Volcano 2의 757개, Saturn 2의 951개, Volcano 3의 896개를 모두 검증했다. 네 제품에 각 136개의 내부 값이 남았다. Micro는 가상 MIDI CC 128개 전체를 확인했다. 자동 Studio Pro 프리셋은 22종이 통과했다. Pro-Q 4는 R19의 별도 내부값 쓰기를 포함할 때 736개가 정확히 일치한다. Twin 3는 R28에서 `Ambient Mover`와 1,509개 일치를 확인했다. One과 Twin 2도 각각 프로그램 1과 5의 프리셋이 재생 후 표시됐다. 두 경우의 내부값 한 개와 프로그램 0 동작, Pro-Q 4 효과 MIDI 라우팅, 각 제품의 전체 쓰기와 프리셋, 그리고 [11월 18일의 내장 대기열](LOOP_HANDOFF_2026-11-18.md#11-빠짐없이-이어갈-28개-완료물)을 이어간다.

2026년 11월 18일 재개 실행은 오전 6시 이동 전에 종료했다. 공개 저장소 보호·검증된 코드의 메인 병합·README 갱신을 완료했다. [당시 전체 대기열](LOOP_HANDOFF_2026-11-18.md)과 [진행 기록](PROGRESS_2026-11-18.md)을 보존했다. 11월 18일의 오전 6시 마감은 그 실행에만 해당했다.

2026년 11월 17일 재개 작업은 사용자가 지정한 오후6시 마감에 맞춰 안전한 경계에서 중단했다. Native59 R81 실제27요청과 마지막 정적 조사를 완료했고 앱·MCP owner·분석 엔진을 모두 닫았다. 당시 재개 기준은 [11월 17일 인수인계](LOOP_HANDOFF_2026-11-17.md), [진행 기록](PROGRESS_2026-11-17.md), `RESUME_STATE.json`이다. 자동 재개는 없다. **진행 재개해** 한마디로 남은 대기열을 이어간다.

11월 15일에는 이동 일정에 맞춰 앱·MCP owner·Ghidra/REA 분석 엔진을 모두 닫고 중단했다. 그날의 종료 시각은 현재 마감이 아니다. 기존 작업 이력과 미완료 대기열은 [11월 15일 인수인계](LOOP_HANDOFF_2026-11-15.md)에 보존했다.

## 재개 순서

사용자가 **진행 재개해**라고 하면 다음 순서로 읽고 미완료 대기열을 이어간다.

1. 저장소 `AGENTS.md`와 사용자의 최신 지시를 읽는다.
2. `RESUME_STATE.json`의 `resume_document`, `current_execution`, `next_units_in_order`를 읽는다.
3. [최신 인수인계](LOOP_HANDOFF_2026-11-20_LIVE.md)와 [11월 18일의 전체 대기열](LOOP_HANDOFF_2026-11-18.md#11-빠짐없이-이어갈-28개-완료물)을 읽는다. 11월 17일 문서는 완료한 증거의 역사다.
4. Git, 현재 설치 파일, 프로세스, 두 잠금, 저장본과 장치 상태를 새로 확인한다.
5. 필요한 다음 유한 단위에 새 문서·세션·인스턴스 바인딩을 만든다.

완료한 unit64, 대규모 파라미터 검사, 프리셋 사례와 과거 실패 연결을 반복하지 않는다.
과거 runtime token을 새 연결에 재사용하지 않는다. 이번 이동 마감은 해당 날짜의 이력이며, 재개할 때 새 세션의 현재 마감으로 재사용하지 않는다.
앱 초기화를 마친 뒤 MCP owner를 시작하는 순서는 실제로 동작했지만, 시작 정체의 인과적 해결로 확정하지 않는다.

R83·R84·R85는 종료한 예비 실험이다. 당시 후보의 설치 증거는 [11월 18일 인수인계 15절](LOOP_HANDOFF_2026-11-18.md)에 보존했다. 실제로 준비와 정리를 한 번 왕복한 Native60 R89의 새 증거와 함께 보되, 과거 후보 파일을 현재 설치 증거로 재사용하지 않는다.
문서만 바뀌면 같은 제품을 다시 빌드하거나 설치하지 않는다.

고정 43개 중 17개 완료, 26개 잔여다. 소프트웨어 22개와 하드웨어 4개를 구분한다.
프리셋은 42/46종과 81사례, 이름은 6866/7112개다. 이 분모를 서로 환산하지 않는다.

직접 armed 상태·완료 시각, 숨은 파형 메모리 복원, 비활성 C 표시 차이는 남으므로 전체 CONTROL-SCOPE 완료 수는 올리지 않았다.
Vocal r69/r70의 집계값·동적 접근 예상 실패는 보존했다. 새 r71의 36요청·원본6장 host/UI 왕복과 전체26복원을 독립 수용해 CONTROL-VOCAL을 완료 처리했다. 오디오 신호와 저장 지속성은 별도다.
실패한 연결을 계속 쓰거나 계획되지 않은 역변경을 보내지 않는다.

## 유지할 사용자 결정

- 공식 8.1.1 설치 파일 대조는 사용자가 생략했다. 설치 경로나 MyFender 로그인을 다시 요청하거나 기다리지 않는다.
- Volt 276과 Keystation88 MK3는 11월 18일 USB로 재연결했다. 그날의 오전 6시 마감은 종료됐다. 장치 의존 단위 전에는 연결 및 루프백 배선을 다시 확인한다.
- Hopper를 사용하지 않는다. 추가 분석에는 Ghidra와 REA의 기존 증거를 활용한다.
- 사용자 보고는 한국어, 내부 지시는 한국어 또는 영어만 사용한다.
- branch와 PR 제목에 `codex`를 쓰지 않는다.
- 실제 사용 가능하고 검증한 단위마다 별도 PR을 올린다. 필수 검사 완료 즉시 main에 병합하고 후속 검증이 필요한 연구는 인수인계에 남긴다. Native60 초안 PR #6은 닫혔고 연구 브랜치는 보존했다.
- 원본 곡·오디오·로그·로컬 경로·독점 앱 리소스를 Git에 넣지 않는다.
- 중단 후에는 새 재개 지시 없이 실제 검증을 자동 시작하지 않는다.

FabFilter 시험의 Native 확장은 59다. 검증용 CLI와 관리 자산의 버전을 현재 체크포인트에서 확인한다. Native60 후보를 재개할 때는 11월 18일 인수인계 15절의 보존 파일과 정상 재바인딩 절차를 따른다. 현재 설치를 Native60 설치 근거로 사용하지 않는다.

이전 [11월 12일 인수인계](LOOP_HANDOFF_2026-11-12.md)와 [11월 10일 인수인계](LOOP_HANDOFF_2026-11-10.md)는 역사적 증거다.
그 문서의 과거 시작 단위를 다시 실행하지 않는다.
