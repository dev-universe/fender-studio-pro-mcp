## 반복 승인 요청을 줄이는 실행 방식

사용자는 다른 일을 하므로 단계마다 나타나는 터미널 입력 승인에 응답하기 어렵다고 알렸다.
필요한 작업은 기존 허용 범위에서 계속 진행하도록 요청했다.
샌드박스 밖의 대화형 터미널에 매 RPC 묶음마다 입력을 보내던 실행 방식을 바꾼다.
검토한 유한 검증 단위를 한 작업으로 승인받아 실행하고, 진행 상태는 workspace의 로그로 읽는다.
관리형 승인 자체를 대신 클릭하거나 보안 설정을 해제하는 방식은 사용하지 않는다.

Native32의 대화형 단위는 Mode-on과 Mode-off-retained의 전체 값 검사까지 통과했고,
Mode-on에서도 캡처한581바이트 상태의 해시가 원본과 같았다.
실행 방식 전환 시점에는 마지막 명시적 pitch-null 복원과 최종 체크포인트가 남아 있었다.
이 단위는 완료로 집계하지 않고 저장 없이 폐기했다. 앱과 owner49를 순서대로 종료했고 저장 원본은 같았다.
새 일괄 단위에서 전체 절차를 끝까지 검증했다. 앞선 중단 기록은 완료로 바꾸지 않았다.

일괄 실행의 UI 준비·종료 신호 파일은 고정된 job ID와 Boolean 상태만 받는다.
추가 명령이나 스크립트를 받는 통로로 사용하지 않는다.
모든 setter·capture·release 전의 Main/fixture 검사와 결과 불명 시 중단 규칙은 유지한다.
MCP owner는 앱 종료 확인 신호가 올 때까지 유지해 종료 순서를 보존한다.
