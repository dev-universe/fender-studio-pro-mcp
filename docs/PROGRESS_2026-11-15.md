그래프 기존48개 질의는 반복하지 않았다. 새 소유자 helper3개와 IID 읽기는223.656초였고 기존149,945,640바이트 Main Program을 실제 warm restore했으며 auto-analysis는 다시 하지 않았다. 공식 고정 소스 대조172.455초로 새 IID가 IActionContext이고 slot3가 getActionJournal임을 확인했다. 따라서 이전 문서/그래프 identity 해석은 버리고 실제 비교를 ActionJournal 포인터 비교로 기록한다. 다른 IID도 IActionExecuter의6개 메서드와 맞았고 script handled=true가 내부 효과 성공을 보장하지 않음을 확인했다. Component 두 파일 대조는 약119초였으며 factory 대응은 해결하지 못했다. 후속 소유자 타입2본문·2정적읽기는 약160초였고 두 읽기 모두0바이트·불완전이어서 null이나 부재로 해석하지 않았다. 구체 factory receiver·+0x200/+0x4a8·정규 Graph 소유권·endpoint/순서/완료 계약은 여전히 남는다. 모든 실행은 정상 close/export/reset/REA0과 원본 checkpoint 보존을 확인했다.

Multi 두 선택 payload는286.656초 동안 구조를 확인했다. 자식 악기9개/3개, 그래프29노드28edge/13노드12edge, MusicFX1개/3개, macro10개/4개가 있다. 외부 package URL은 각각986개·483개이며 실제 내용 설치/해결과 독립 live child·graph·map 복원은 미검증이다. 루트150개만 비교해 전체 중첩 제어로 확대하지 않는다. static 후보와 issued entry의 직접 URL·factory origin도 주장하지 않는다.

Scope 조사는335.716초였다. 실제31개 provider와 shipped view를 대조해 Oneshot은 모드 Toggle, Retrigger는 즉시 Button임을 구분했다. 현재4개 typed action에 Scope는 없다. 일반 scalar 두 번으로 SDK의 max/update=true·min/update=false 펄스를 흉내내지 않는다. 전체31개에 별도 acquisition 완료나 waveform API가 없어, 고정 f1 파형 유지와 바뀐 Tone f2·한 Retrigger 뒤 새 파형을 실제 격자에서 독립 비교할 근거가 필요하다. 먼저 Main0 준비 한 번을 포함한13요청의 화면·읽기 전용 절차를 준비한다. Scope/Tone 값 변경·프리셋·트리거·재생·Save는 이 준비 범위 밖이다.

[정제한 근거](evidence/2026-11-15-graph-scope-multi-prerequisites.json)에 해시와 공식 소스 링크를 보존했다. 이 조사들은 원래 미완료 항목의 선행 조건이며 새 완료물을 추가하지 않았다. 고정14/43완료·29잔여와 프리셋40/46종77사례는 SampleOne 수용 이후 값 그대로다.


정확한 두 클래스 셀의 초기화 참조 조사도160.187초에 종료했다. 반환434개·28개 중 각각16개만 검토했고418개·12개는 미검토로 남겼다. 참조 종류가 없어 write initializer로 확정하지 않았다. 한 singleton 생성자는 root 이름과 두 초기 false flag 등 공식 RootComponent와 강하게 맞았지만 직접 TypeInfo 클래스명이나 Graph 소유권 증거로 수용하지 않았다. 정해둔 Ghidra 조사 범위를 마치고, 기존에 완료한 swapfreqs·reset 동작의 이름 증거를 원래246개 목록에 재사용할 수 있는지 읽기 감사 중이다. 새 실기나 분모 추가는 없다.
